# 插件实现与宿主边界

::: warning 开发版本文档
本页按 2026-09-17 的 ZNet Sink `develop` 提交 [`912d1dc`](https://github.com/zerodenet/znet-sink/tree/912d1dc7d9d9c63259df7e3640784634a276b7a6)核对。插件宿主和 SDK 尚未随 `0.0.1` 稳定版发布；实际能力以安装的客户端制品为准。
:::

ZNet Sink 插件由“客户端宿主、签名安装包、插件组件、插件管理页面”组成。客户端提供隔离执行、权限、存储和生命周期等通用能力，插件实现自己的业务流程。客户端不会替插件实现登录、账号体系、订阅选择、自检结果页面或服务端协议。

## 客户端与插件如何分工

| 客户端负责 | 插件负责 |
| --- | --- |
| 安装、更新、签名与发布者身份校验 | 业务配置、登录和远端服务交互 |
| 权限声明、用户授权、执行前复核与撤销 | 在获批权限和 scope 内调用宿主能力 |
| 启用、停用、升级、卸载及资源回收 | 管理页面、业务状态和自检结果的可视化 |
| 插件详情页的“管理 / 权限 / 关于”外壳 | “管理”区域内部的完整交互 |
| 命名空间、容量、原子写入和短期材料句柄 | 数据格式、迁移内容和业务密文生成 |

插件不能修改客户端外层的名称、版本、发布者、启用状态、权限审查、更新或卸载界面。管理页面只控制自己的沙箱内容。

## 安装来源

插件市场与安装包是两个不同来源：

- 插件中心只发布插件索引、版本、客户端兼容范围、安装包大小、SHA256、签名公钥和作者仓库地址等元数据。
- 安装包保存在作者 GitHub 仓库的 Release 中，客户端直接从该 Release 下载。
- 首次从市场安装时，客户端选择最新的兼容版本。已安装插件的版本查看与更新在插件详情流程中完成。
- 下载完成后，客户端核对大小、SHA256、签名、插件身份、组件声明和兼容范围，再写入本地安装状态。

在线安装会受到插件中心登记的 capability 和 surface 上限约束。插件中心域名不是安装包下载站。

### 本地安装

未上架插件也可以安装。本地安装要求安装包内嵌发布者登记并通过签名验证，客户端会把发布者身份和指纹展示为一次明确的本地信任决定。

本地安装不会把插件自动登记到线上市场，也不会采用线上市场的 capability/surface 上限；发布者身份、包签名、插件身份和客户端兼容性仍然必须通过校验。旧的 v1 包如果没有内嵌发布者登记，只能在客户端已有可信登记可用于匹配时迁移安装。

## 安装包与页面

当前安装包支持：

- `znet-sink.plugin-package.v1`：使用外部可信登记；
- `znet-sink.plugin-package.v2`：可携带签名的发布者登记，用于显式本地安装；
- payload schema `1`，宿主固定为 `znet-sink`；
- 每包最多 8 个组件、4 个页面；
- payload 最大 2 MiB，完整安装包最大 4 MiB，单个管理页面 HTML 最大 512 KiB；
- 当前页面类型为 `management`，对应 surface `znet-sink.ui.management.v1`。

管理页面来自已经验签的包。客户端把它放入隔离 iframe：页面没有同源权限，不能直接联网、提交表单、加载远端脚本或调用 Tauri。客户端注入绑定当前插件身份的 `globalThis.znetPlugin`，页面通过它读取配置、访问存储、发通知、创建回调或调用其他已授权能力。

因此，一个需要登录远端服务的插件应当自行渲染服务地址、账号授权、资源选择和状态页面，但通过 SDK 请求经过客户端批准的网络 origin、浏览器回调、存储或短期材料能力。

## 权限生命周期

安装插件不等于授予权限。客户端按以下顺序处理：

1. 校验发布者、签名、包身份、兼容范围和声明上限。
2. 展示组件申请的必需权限、可选权限及精确 scope。
3. 保存用户批准的声明和授权集合。
4. 每次 SDK 调用重新检查插件身份、组件状态、声明、授权和当前运行代次。
5. 插件升级新增 capability 或扩大 scope 时重新显式申请；未审权限不会继承。

用户授权是持久状态。界面中曾提到的“最多 10 分钟”只适用于一次操作使用的内存材料句柄，不是用户权限十分钟后自动失效。停用组件会保留已批准权限，撤销权限才会清除授权。

停止、撤权、升级、卸载或客户端退出时，宿主会回收对应组件的回调、调度、短期材料、运行句柄和在途工作，防止旧运行结果写回新状态。

## 数据与敏感材料

普通插件存储按“发布者指纹 + 插件 ID”隔离，插件定义值的内容，客户端只负责边界：

| 项目 | 限制 |
| --- | --- |
| `state` | 2 MiB |
| `cache` | 4 MiB |
| 键数量 | 每命名空间最多 256 个 |
| 单值 | Base64 解码后最多 128 KiB |
| 迁移 | 只允许相邻 schema 版本逐步迁移 |

普通存储不是安全保险箱。长期敏感内容应由插件或远端服务生成密文或不透明信封，再写入插件存储。客户端不定义某个插件的加密协议，不持有业务主密钥，也不保存明文账号和密码。

短期材料保存在内存中，按插件、组件和用途隔离，并在使用后清零。单个句柄最长 10 分钟、最多 8 MiB；宿主总计最多 64 个句柄和 16 MiB。受保护配置使用“材料提交 → 可选加密操作 → runtime-only 应用”的通用链路，返回值只包含安全的运行状态摘要。

## 管理界面

插件管理入口采用固定分工：

- **管理**：插件自己的完整页面，可包含登录、选择、同步、自检和业务说明；
- **权限**：客户端展示和修改 capability、scope 与启用状态；
- **关于**：客户端展示签名包中的名称、版本、发布者、ID、仓库和 surface；
- **更新与卸载**：由客户端统一执行并清理宿主资源。

自检属于插件能力，正常结果应由插件页面渲染为用户可读的状态、问题和下一步操作。客户端可以保留折叠的开发诊断信息，但不应把原始 JSON 当作普通用户的主要结果。
