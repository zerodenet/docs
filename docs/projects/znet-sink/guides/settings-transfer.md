# 迁移设置与管理内核

先区分三类数据：代理配置/订阅决定可用节点；客户端设置控制本机使用方式；诊断资料用于排障。一个设置导出文件不会备份全部数据。

## 当前配置的本地修改

设置页显示“本地修改 · 仅当前配置”时，采用以下顺序：**当前配置的本地修改 → 订阅或导入文件的值 → 缺失项使用默认值**。

例如订阅端口是 7891，你在“设置 → 网络”改成 7877 并保存后：

- 只有当前配置使用你的 7877，订阅原文不变
- 该订阅以后更新仍保留此修改；切到另一份配置不会带过去
- 点击“恢复配置值”后重新采用订阅最新端口
- 已开启的系统代理在应用成功后跟随实际端口；原本关闭的代理不会因此开启

DNS、TUN、绕过及测速等也应先看设置页的“来自配置/本地修改”提示，再保存。如果从只提供“保存缺省值”的旧客户端升级，不要把旧的全局设置当成每份配置都有的本地修改；逐份确认实际生效值。

## 导出并导入

1. 在专业模式“设置 → 高级配置”找到“内核配置迁移”，点击“导出”并保存 JSON 文件。
2. 在目标电脑的相同入口点击“导入”，选择文件，等待校验和应用结果。
3. 重新核对 DNS、TUN、绕过网段及运行偏好，尤其是与原电脑不同的内网环境。
4. 单独安装 Zero 内核，添加或导入代理来源，再验证连接。

当前导出格式为 `znet.client-kernel-settings.v3`；新版仍可读取旧 v1/v2/v3 设置及旧应用配置中的可迁移部分。旧客户端可能无法读取新版格式，不要手工改格式标识强行导入。

迁移包含可移植的客户端缺省设置和运行偏好，**不包含**内核可执行路径、订阅/代理配置、日志，以及绑定具体配置 ID 的本地修改。换电脑时，需要另行保留普通代理配置或重新添加来源；插件来源按其登录和恢复流程处理。

运行中导入可能重启受管内核或恢复 TUN，现有连接会中断。失败或结果不确定时，先查看提示并确认实际状态，不要重复导入。

## 升级、重装与回退 {#_0-0-1-安装与恢复}

客户端、Zero 内核与插件分别更新。升级前阅读目标版本的变更和兼容要求，不必追求相同版本号。

重装或回退前，保留原配置和应用数据，关闭系统代理与 TUN，再使用[官方发布页](https://github.com/zerodenet/znet-sink/releases)中对应平台的安装包。较新客户端生成的数据不保证可由旧版直接读取；不要直接覆盖唯一备份。

升级后先验证原来能用的连接，再恢复 TUN 或插件等附加功能。遇到数据格式不兼容时，保留备份和错误信息，不要用旧版反复覆盖新数据。

## 安装与选择内核

在“设置 → 版本管理”打开内核版本管理，选择渠道和版本安装。也可以选择已经存在的 `zero` / `zero.exe`。页面应显示实际使用的路径和版本。

版本列表中的稳定版、测试版、开发版是不同渠道；列表出现新版本不表示它已经成为当前内核。客户端升级也不会保证当前内核同步升级。

升级前保留可恢复的版本与配置。升级后依次验证内核启动、本地代理入口、系统代理和网站访问，最后检查需要的 TUN/DNS 功能。自动检查可能使用缓存，需要立即确认时手动刷新。收到“TUN 恢复失败”时，按 [TUN 状态说明](./tun#看懂开关与状态)处理。
