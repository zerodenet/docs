# 故障排查

先记下客户端版本、Zero 内核版本和第一条错误。每次只改一项，再重试目标网站；不要同时换 DNS、节点、TUN 和代理端口。

下面按[当前候选版](../#文档适用版本)核对；安装旧版时先确认功能是否存在，尤其是插件和当前配置的本地修改。

## “开启服务”不可用

1. 在“设置 → 版本管理”确认有有效的 Zero 可执行文件和版本。
2. 在概览选择当前配置。仅保存订阅不够，还要同步成功并选中来源。
3. 打开概览自测提示，处理无效配置或端口占用。
4. 没有本地代理入口时，检查来源配置；当前候选版不会替显式 `inbounds: []` 自动添加入口。

简约模式电源按钮需要同时开启系统代理和 TUN。若暂时无法取得 TUN 权限，切到专业模式，按[第一次连接](./first-connection)只开启系统代理。

## 内核启动后仍无法连接

先区分“内核进程存在”和“内核已就绪”。查看应用/内核日志中的第一条启动错误，常见原因是配置字段无效、节点引用不存在或端口被占用。

确认本地代理端口可用后，再看系统代理是否开启。界面提示某项能力不支持时，核对实际安装的内核，不要认为升级客户端就同时升级了 Zero。

## TUN 无法开启或开启后断网

1. 确认系统本身可以联网；先关闭其他可能同时接管路由的工具进行比较。
2. 检查权限。Windows 通常需管理员权限，Linux/macOS 需允许创建 TUN 与修改路由。
3. 检查地址是否为有效 CIDR、MTU 是否在 `576–65535`、内核是否支持所选双栈或 DNS 劫持功能。
4. 网络切换后使用界面的“立即重试”恢复检查，等待结果。
5. 仍然断网时关闭 TUN，确认普通网络恢复，再保留首条错误反馈。

Windows 提示 Wintun 缺失时，先检查所用 Zero 发布包是否完整。内核启动成功但 TUN 恢复失败需要单独处理；状态未知不能当作已关闭。

当前候选版保存 TUN 设置属于当前配置，运行中应用可能重建网卡；切换或更新来源改变 TUN 参数时，按提示先关闭再操作。不要反复保存制造更多中断。详见 [TUN 指南](./tun)。

## TUN 已开启但 DNS 路径不符合预期

在“设置 → 域名解析”检查模式和上游是否可达，确认保存结果，再检查流量接管中的 DNS 劫持。

普通 53 端口劫持无法解密应用自带的 DoH/DoT/DoQ，也不保证恢复 ECH 隐藏的主机名。系统代理与 TUN 同时开启时，浏览器可能走本地代理入口；查看连接详情确认实际路径。

内网域名问题按 [DNS 指南](./dns#给内网域名单独解析)分别检查解析服务器、Fake-IP 排除和绕过网段。

## 已连接但应用没有走代理

- 浏览器也不通：核对当前配置、所选节点、代理模式及内核错误；试用另一个已知可用节点
- 浏览器可用，只有某个应用不通：检查该应用是否遵循系统代理，必要时手动填写本地 HTTP/SOCKS5 地址
- Linux 系统代理不生效：当前自动集成使用 GNOME `gsettings`，其他桌面环境可能需手动设置应用代理
- 只在 TUN 下失败：单独关闭 TUN，用系统代理比较，按上方 TUN 排查
- 只有公网 IP 检测失败：测试自己的目标网站；检测服务不可达不等于全部代理失败

概览显示的实际本地地址和端口才是应填写的值，不必然为 7890。不要让多个代理工具同时改系统设置。

## 订阅同步失败

先看错误属于下载、跳转、解码还是转换：

- 下载或授权错误：检查网络、链接有效期和服务端令牌
- 返回登录页/网页：重新获取真正的订阅链接，不要强行切换格式
- Zero 格式错误：远程 Zero 订阅要求 Base64 Zero JSON；普通 JSON 文件从配置页导入
- User-Agent 不符：Zboard 普通订阅通常留空使用默认标识，其他服务按其要求填写
- 插件托管来源：回到来源插件处理登录、权限或刷新

单次同步失败不会被当作新的可用配置。恢复后重新同步，并确认概览仍选择正确的来源。详见[订阅管理](./subscriptions)。

## 节点或测速状态没有更新

确认当前配置、策略组和内核状态，等待一次完整测试结束。自动 URLTest 组由内核选择，不能当作普通手选组；显示超时也可能只是探测地址不可达。

使用真实目标网站比较。停止测速可以取消未提交的排队任务，但已发出的请求仍可能返回结果。仍无更新时记录操作时间及首条错误，不要连续点击重复整批测试。

## 实时连接切换配置后异常

确认概览已切到新配置，再发起新的网络请求，清除列表筛选并恢复刷新。历史记录与活动记录不是同一份列表。

如果新请求持续不出现，保存切换前后的日志和发生时间，再按下方方式反馈。不要先清空历史或重装，避免丢失诊断信息。

## 打开终端没有反应

Windows 托盘终端需要 `pwsh.exe` 或 `powershell.exe`，并会先等待本地代理端口。检查内核、当前配置和端口，再查看应用日志中的终端启动错误。

这个入口不是所有系统通用的终端启动器；其他平台可在目标应用或终端中自行使用本地代理地址。

## 插件安装后不能用

安装包和运行授权是两步。打开插件详情，检查配置、“权限”和启用状态。当前正式版 0.0.1 没有插件入口；兼容渠道、签名错误及卸载影响见[插件指南](./plugins)。

## 仍无法定位

按[数据与诊断](./data-and-diagnostics#导出诊断包)导出材料，检查敏感内容后，到 [ZNet Sink Issues](https://github.com/zerodenet/znet-sink/issues)提供：

- 客户端版本、Zero 内核版本、操作系统与架构
- 简约或专业模式，以及系统代理/TUN 是否开启
- 问题发生时间、能重复的步骤、期望与实际结果
- 是否刚更新、换网络、同步订阅或切换配置
- 最早出现的错误及相关脱敏日志

不要公开完整订阅链接、代理密码、账号令牌、私人域名或配置原文。
