# 本地代理、系统代理与节点测速

本页解决三件事：给指定应用填写代理地址、保留内网访问、选择并测试节点。首次连接步骤见[完成第一次连接](./first-connection)。

## 本地代理入口

Mixed 入口可以同时接受 HTTP 和 SOCKS5 代理请求。客户端缺省入口为 `127.0.0.1:7890`，但**应以概览显示的实际地址和端口为准**；来源配置可能使用其他值。

不遵循系统代理的应用，可在它自己的设置中填写：

- HTTP/HTTPS 代理：主机 `127.0.0.1`，端口为当前本地代理端口
- SOCKS5 代理：相同主机和端口；有“通过代理解析域名”选项时按应用需要启用

先确认内核正在运行且该端口可用，再测试应用。不要把 Zero 的管理/IPC 地址填入 HTTP/SOCKS5 代理栏。

在“设置 → 网络 → 代理端口”修改监听地址和端口。修改只属于当前配置，订阅更新保留它，“恢复配置值”重新采用来源值。

来源字段缺失时可以补齐缺省入口；完整自定义入口会保留。客户端尊重显式 `inbounds: []`，不会擅自创建入站。没有特别的局域网共享需求时保留回环地址，不要随意改成对外监听。

## 系统代理

专业模式可在概览独立开启系统代理。客户端先检查内核与本地入口，再设置操作系统代理；关闭时尝试恢复接管前保存的设置。

- Windows 使用系统代理设置；已有绕过、分协议代理或 PAC 可能影响访问
- macOS 按网络服务配置系统代理，网络服务变化后需要重新检查
- Linux 当前使用 GNOME `gsettings`；其他桌面环境不保证自动生效

如果目标应用不遵循这些设置，请使用它自己的代理选项，或进一步配置 [TUN](./tun)。系统代理不会自动接管所有 UDP、WebRTC 和 DNS。也不要让多个代理程序同时修改系统代理。

## 统一绕过规则

访问家庭设备、公司内网或 VPN 目标时，希望保留原来的连接路径，可在“设置 → 网络”编辑“绕过规则”：

1. 检查列表中的默认本机和局域网规则；需要补回默认列表时点击“恢复默认”。
2. 每行添加一个需要绕过的 IP、CIDR 或域名，例如 `192.168.50.0/24`、`intranet.example.com`、`*.example.com`。
3. 保存并等待应用结果，再分别验证内网服务和外部网站。

统一绕过协调系统代理例外、TUN 排除和内核直连，规则/全局模式均可生效。但并非每种系统代理都能表达所有 CIDR；部分直连仍由内核执行，因此“直连”不等于流量完全不经过内核。

域名规则需要请求中有可用域名。应用只提供 IP，或加密 DNS/ECH 隐藏了域名时，不能保证按域名绕过；可使用已知目标网段。公司内网还可能需要[专用 DNS 分流](./dns#给内网域名单独解析)。

该功能需要内核声明 `route_bypass_v1`。网段修改可能重建 TUN 并中断连接；保存的修改属于当前配置，不会自动复制到其他配置。

## TUN 与系统代理

系统代理服务于遵循操作系统代理设置的应用；TUN 接管进入虚拟网卡的流量。两者可以同时开启。

专业模式分别控制；简约模式中央电源按钮同时控制系统代理和 TUN。如果只想让浏览器走代理，使用专业模式的系统代理开关。详情见 [TUN 指南](./tun)。

## 打开代理终端

Windows 托盘菜单的“打开终端”会等待本地代理入口可用，再打开 PowerShell，注入以下环境变量：

| 变量 | 形式 |
| --- | --- |
| `HTTP_PROXY` / `HTTPS_PROXY` | `http://<实际主机>:<实际端口>` |
| `ALL_PROXY` | `socks5h://<实际主机>:<实际端口>` |
| `NO_PROXY` | 根据当前绕过规则生成，具体语法支持取决于命令行工具 |

也会设置对应小写变量。变量只作用于新终端及子进程，不改变全局用户环境，也不保证每个命令行程序都会遵循这些变量。

其他平台可使用托盘“复制代理环境变量”，检查后粘贴到自己的终端。可以用实际需要的命令测试；终端可用而其他应用不可用时，优先检查那个应用的代理设置。

## 节点与 URLTest 测速

1. 确认概览中的当前配置正确，内核已就绪。
2. 打开“节点”，选择要使用的策略组。
3. 对需要的节点执行测速，等待本批次结束；新版提供“停止测速”以取消尚未提交的排队目标。
4. 在允许手动选择的组中选择节点，再实际访问目标网站。

URLTest 是自动选择组，当前成员由内核决定，不能把所有卡片都当作可手动选择的节点。嵌套组显示的延迟也要结合它当前实际选中的出口理解。

测速显示的是探测地址的响应延迟，不是带宽。某个探测 URL 被阻断时，节点仍可能访问其他网站；“超时”也不等于订阅失效。大量节点可能需要更久，不要连续点击重复发起整批测试。

节点页也提供配置中的 WireGuard 端点视图。端点可由路由或 DNS 引用，但仅打开该视图不会改变策略选择。

## 历史记录的作用域

节点延迟历史属于当前配置和对应节点/策略组。切换配置后，不应把同名节点的旧结果当成新配置的测试结果。

查看历史适合比较同一节点最近的变化；判断现在能否使用，仍需重新测速并实际访问。

## 排查顺序

1. 确认当前配置、策略组和所选节点。
2. 查看本地代理是否可用，内核是否已就绪。
3. 等待一次测速结束，查看该次首条失败信息。
4. 用实际目标网站验证，区分探测站点失败和真正的代理连接失败。
5. 仍无结果时查看应用/内核日志，按[数据与诊断](./data-and-diagnostics)保存材料。
