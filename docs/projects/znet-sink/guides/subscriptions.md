# 订阅管理

订阅由 ZNet Sink 拉取、解析并转换成本地代理配置。订阅记录和生成的配置都保存在客户端本地。

## 支持的格式

当前支持：

- Zero JSON
- Zero Base64 JSON
- Clash YAML
- Clash Base64 YAML
- 自动检测上述格式

原生 Zero 内容优先按 Zero 配置处理。Clash 内容会转换为 Zero 配置。转换能力不等同于完整兼容所有 Clash 扩展字段；同步完成后仍应检查生成的节点、策略组和规则。

## 添加订阅

1. 打开“订阅”。
2. 点击新增订阅，填写名称和订阅 URL。
3. 通常保留“自动检测”；只有服务端格式固定且检测失败时再手动指定。
4. 根据需要选择手动更新或 30 分钟、1 小时、6 小时、12 小时、24 小时的更新周期。
5. 保存并执行同步。

同步成功后，订阅会创建或更新一份本地代理配置。新生成的配置不会无条件抢占当前配置；需要时请在“配置”页确认并启用。

## 本地代理入口

订阅配置需要包含可供桌面应用连接的本地入站。同步时 ZNet Sink 会：

- 保留完整可用的自定义 `mixed`、`http` 或 `socks5` 入站；
- 补全不完整的本地代理入站；
- 对只有 TUN 或没有本地入站的配置添加受管 Mixed 入站；
- 新建受管入口时默认使用 `127.0.0.1:7890`。

受管入口的端口可以在“设置 → 常规”中修改。完整行为见[本地代理、系统代理与节点测速](./proxy-and-probes)。

## 同步语义

- 禁用订阅后，不参与批量和定时同步。
- 手动同步会立即拉取远端内容。
- 同步失败会保留错误信息，原有可用配置不会因为一次网络失败被当作成功结果覆盖。
- Clash `rule-providers` 和引用它们的规则会按客户端当前支持边界转换为本地规则集。
- 原生 Zero 配置中的当前支持字段会尽量保留，包括 Mieru 等协议的原生字段。
- 旧版本生成的订阅配置会在同步时串行迁移，避免同一记录被多个更新任务同时改写。

## Base64 响应

部分服务端会把原生 Zero 配置以 Base64 文本返回。Base64 不是加密；解码后仍可能包含节点地址和订阅凭据。格式选择为“自动检测”时，客户端会识别支持的 Base64 JSON/YAML 表示。

如果同步得到网页、跳转页或其他非订阅内容，自动检测会失败。此时检查 HTTP 状态、最终 URL、订阅令牌和服务端模板，而不是反复切换 JSON/YAML 格式。

## 安全提示

订阅 URL 可能包含访问凭据。不要把完整 URL 放进公开问题、截图或普通日志。导出的诊断包会排除订阅地址，但发送前仍应自行复核内容。
