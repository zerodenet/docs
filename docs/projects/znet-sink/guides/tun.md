# TUN 模式

ZNet Sink `0.0.16-rc.8` 正式接入 Zero `0.0.16` 的 TUN 运行时。TUN 与系统代理是两个独立入口：系统代理主要覆盖遵循操作系统 HTTP/HTTPS 代理设置的应用，TUN 则由 Zero 创建虚拟网卡并接管系统路由。

## 使用前提

启用 TUN 前确认：

1. “设置 → 内核”中已经选择支持 TUN 的 Zero `0.0.16` 系列内核；
2. 当前配置能够正常启动并具有可用出站；
3. ZNet Sink 具备当前操作系统创建 TUN 和修改路由所需的权限；
4. 没有其他 VPN、TUN 客户端或路由脚本持续争用同一套路由。

Windows 官方 Zero 发布包会准备 Wintun 运行组件。ZNet Sink 也会处理旧版本遗留的受管 Wintun 运行状态；如果系统仍提示权限或驱动问题，应优先查看客户端给出的具体错误，而不是重复安装未知来源的 DLL。

## 本地 TUN 设置

在设置中的 TUN 页面可以配置 ZNet Sink 自己管理 TUN 时使用的缺省参数：

| 设置 | 默认/规则 | 作用 |
|------|-----------|------|
| 网卡名称 | 留空 | 留空时由 Zero 选择接口名称 |
| 入站标签 | `proxy` | TUN 流量进入 Zero 后使用的 inbound tag |
| 主地址 | `10.0.0.1/24` | 必须使用 CIDR |
| 第二地址 | 留空 | 双栈时可指定另一地址族的 CIDR |
| MTU | `1500` | 允许 `576–65535` |
| 双栈接管 | 开启 | 同时准备 IPv4 / IPv6 地址和路由 |
| DNS 劫持 | 当前关闭 | rc.8 暂不提供应用托管的 DNS 劫持 |

TUN 正在由 ZNet Sink 管理运行时，启动参数会锁定。需要修改地址、MTU、tag 等参数时，先关闭 TUN再保存设置。

## 配置所有权

ZNet Sink 区分两种 TUN 来源：

- **配置管理**：当前活动配置显式定义 `runtime.tun`；
- **应用管理**：当前配置没有定义 TUN，由 ZNet Sink 使用本地缺省值调用 Zero 的 TUN 生命周期。

如果活动配置显式定义了 `runtime.tun`，它优先于本地 TUN 缺省值。设置页仍允许维护本地缺省值，但这些值只会在以后启用一份没有定义 `runtime.tun` 的配置时使用。

不要为了让应用托管 TUN 生效而把本地设置写回生成的 Zero 配置。ZNet Sink 会独立保存自己的 desired state，并在内核重启后重新协调需要的运行状态。

## 启用、关闭与配置切换

应用托管 TUN 使用 Zero 的命令生命周期启动和停止，而不是自行修改系统路由。

运行过程中 ZNet Sink 会：

- 读取 Zero 返回的真实 TUN 状态；
- 在内核重启后重新应用仍然有效的应用托管 TUN desired state；
- 切换配置时先判断新旧配置的 TUN 所有权，再完成 handoff；
- handoff 失败时尽量恢复切换前的运行状态，而不是留下半套 TUN；
- 保留配置显式声明的 TUN，不用本地默认值覆盖它。

因此配置切换后的判断依据应是当前配置身份和 Zero 的实际 TUN 状态，不要只根据按钮是否刚被点击推断运行结果。

## 与系统代理同时使用

rc.8 不要求启用 TUN 后强制关闭系统代理。简约模式可以同时保留系统代理和 TUN：

- 遵循系统代理的应用继续通过本地 Mixed 入口连接；
- 其他被系统路由接管的流量通过 TUN 进入 Zero；
- 两种入口最终仍使用当前活动配置的路由与出站。

这不代表同一条连接会被计费或代理两次；它们是两种进入内核的方式。排查问题时应先判断目标应用实际使用的是系统代理还是 TUN。

## rc.8 的 DNS 限制

**ZNet Sink `0.0.16-rc.8` 暂时关闭应用托管 TUN 的 DNS 劫持。** 设置页中的“DNS 劫持”固定不可用，因为客户端尚未提供与 Zero TUN 配套的完整 DNS 配置能力。

这意味着：

- 开启 TUN 不等于客户端已经接管所有 DNS 请求；
- 不应把当前版本的 TUN 开关描述为完整的 DNS 防泄漏方案；
- 活动 Zero 配置自行定义的 `runtime.tun` 不受本地禁用开关覆盖，具体行为由该配置和内核能力决定。

如果目标是验证 DNS 是否通过代理路径，应单独检查当前 DNS 配置和实际解析流量，不要只看 TUN 是否显示“已开启”。

## 状态与常见错误

### 提示权限不足

TUN 创建、路由写入和底层接口操作需要系统权限。按客户端给出的平台提示提升运行权限后重试；如果仍失败，保留第一条 TUN 错误和内核日志。

### TUN 已开启但没有流量

依次检查：

1. 当前活动配置是否已经成功应用；
2. TUN 状态是否健康；
3. 当前配置是 profile-owned 还是 app-owned TUN；
4. 系统默认出口是否刚发生 Wi-Fi、VPN 或网关切换；
5. 是否有其他软件持续重写系统路由。

Zero `0.0.16` 会在底层出口变化后重新协调 TUN 路由；如果仍然失败，应查看内核的出口接口和路由错误，而不是手工叠加静态路由。

### 配置切换后 TUN 状态不对

先确认新配置是否显式包含 `runtime.tun`。如果有，则应以配置管理状态为准；如果没有，则检查 ZNet Sink 保存的应用托管 desired state 是否仍为开启。配置切换过程中发生失败时，应用会尝试恢复原状态，相关原因会记录到日志。
