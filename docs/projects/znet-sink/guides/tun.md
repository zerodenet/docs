# TUN 接管与网络切换

浏览器已能使用系统代理，但其他应用不遵循系统代理设置时，可以使用 TUN。它创建虚拟网卡并调整路由，需要操作系统权限和兼容的 Zero 内核。先完成[第一次连接](./first-connection)，再增加这一层接管。

本页设置步骤按[当前候选版](../#文档适用版本)编写。0.0.1 的 TUN 设置来源和保存方式不同，不要照新版的“本地修改”语义判断旧版状态。

## 确认参数来源

切到专业模式，打开“设置 → 流量接管”。先确认概览中选中的是你想修改的配置。

- 显示“来自配置”：使用订阅或导入文件中的参数，缺失项使用客户端默认值
- 显示“本地修改 · 仅当前配置”：你保存过该配置的修改；订阅更新仍保留它
- 点击“恢复配置值”：删除该项本地修改，重新采用来源的最新参数

导入含有 TUN 参数的配置，不表示客户端已经获得权限或已经开始接管；应以运行状态为准。

## 配置并开启

1. 在“设置 → 版本管理”确认已安装兼容的 Zero 内核。
2. 打开“流量接管”，无特别需要时保留地址、网卡名、入站标签和 MTU。地址使用 CIDR；MTU 范围为 `576–65535`。
3. 需要同时接管 IPv4/IPv6 时开启“双栈接管”。第二地址可留空自动选择；物理网络没有 IPv6 出口时，开启双栈不会凭空提供 IPv6 网络。
4. “TUN 接管网段”留空表示全部目标，填写时只接管指定网段。家庭或公司内网例外在“设置 → 网络 → 绕过规则”中填写，例如 `192.168.50.0/24`。
5. 如果要接管普通 DNS 查询，先保存 [Real DNS 或 Fake-IP](./dns)，再启用 DNS 劫持。也可以关闭劫持，使用系统 DNS。
6. 保存后回到概览开启 TUN，处理权限提示并等待状态确认。

**完成标志：TUN 显示运行且没有接管健康错误，目标应用能访问。** 仅网卡存在或网页能打开不够；专业模式的连接详情可帮助确认流量是否来自 TUN。

Windows 通常需要管理员权限；Linux/macOS 需要创建 TUN 与修改路由的权限。没有权限时先使用系统代理，不要将全部网络错误都当成节点不可用。

## 运行中修改参数

在当前候选版设置页修改并点击“保存并应用”，运行中的 TUN 可能被重建，已有连接会短暂中断。请等待完整结果后再操作。

“保存设置”“TUN 正在运行”“新参数已应用”不是同一件事。显示失败或结果未确认时，刷新状态并查看错误；不要连续保存或同时切换配置。

订阅更新或切换配置若改变正在使用的 TUN 参数，客户端可能要求先关闭 TUN。这时先关闭并确认停止，再更新或切换配置，最后重新开启。原本关闭的 TUN 不会仅因为保存参数而自动开启。

## 看懂开关与状态

| 显示情况 | 下一步 |
| --- | --- |
| 已运行，无接管错误 | 验证目标应用；必要时查看连接入站与出站 |
| 保存为开启，但未运行 | 处理启动或恢复错误，再重试 |
| 状态未知或待确认 | 先刷新；通信失败不等于 TUN 已关闭 |
| 内核启动成功，TUN 恢复失败 | 分别检查内核和 TUN，保留首条恢复错误 |

专业模式的系统代理和 TUN 是独立开关。简约模式电源按钮同时管理两者。停止接管后应确认两项都达到预期状态，不能只看内核进程是否还在。

## Wi-Fi、网线或 VPN 切换

切换网络后无法访问时：

1. 先确认操作系统本身已连网，Wi-Fi/VPN 已完成连接。
2. 查看 TUN 健康提示；界面提供“立即重试”时可执行一次恢复检查。
3. 分别验证域名解析和目标应用访问。
4. 内网访问失败时，检查实际目标网段是否加入[绕过规则](./proxy-and-probes#统一绕过规则)，以及系统 VPN 路由是否存在。
5. 仍失败时先关闭 TUN，确认普通网络恢复，再保存相关日志并按[故障排查](./troubleshooting)反馈。

裸 IPv6、NAT64、应用自己的加密 DNS 和 ECH 等场景不能仅凭“开启双栈/DNS 劫持”保证可用。实际结果还取决于所选内核版本和当前网络。
