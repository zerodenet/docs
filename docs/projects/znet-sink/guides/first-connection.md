# 完成第一次连接

第一次连接需要同时满足三个条件：内核组件已就绪、存在有效代理配置、其中一份配置已设为当前配置。

## 1. 准备代理配置

打开“配置”，点击“新建配置”。ZNet Sink 支持两种来源：

- **本地文件**：选择一个 Zero JSON 配置文件。
- **粘贴 JSON**：直接粘贴并保存配置内容。

保存时启用“设为当前”，或者在配置列表中对已保存配置执行“启用”。连接时只会使用当前配置。

如果配置来自远程订阅，可以改用[订阅管理](./subscriptions)。

## 2. 检查概览状态

回到“概览”，展开“系统自测”并处理阻塞项。常见阻塞包括：

- 没有当前代理配置；
- 配置内容为空或无法导出；
- 内核路径无效；
- 本地代理监听地址或端口不可用。

## 3. 开启服务

点击“开启服务”后，客户端会按顺序：

1. 导出当前配置；
2. 启动或复用由客户端管理的内核进程；
3. 等待内核健康检查和本地代理端口就绪；
4. 设置系统代理指向本地代理端口。

如果内核已经运行但系统代理未开启，按钮会显示“开启系统代理”。

## 4. 按需启用 TUN

`0.0.16-rc.8` 可以配合兼容的 Zero 0.0.16 运行 TUN。首次启用前先确认当前配置的 TUN 来源：

- 配置显式包含 `runtime.tun`：由当前配置管理 TUN，客户端显示配置来源；
- 配置没有 `runtime.tun`：使用“设置 → TUN”中的客户端缺省值。

本地缺省值可以设置网卡名称、入站 tag、主地址、第二地址、MTU 和双栈接管。主地址与第二地址使用 CIDR；MTU 允许 `576–65535`。

TUN 会修改系统路由，需要对应平台的管理员权限。权限不足时应先按客户端提示提升权限，不要反复开关 TUN。Windows 官方 Zero 0.0.16 发布包已包含所需 Wintun 组件。

当前 ZNet Sink 的本地“DNS 劫持”设置暂不可用并固定关闭，因为客户端还未提供完整的 Zero DNS 配置。需要 DNS/Fake IP 等能力时，以实际活动配置和当前内核能力为准，不应仅凭“TUN 已开启”判断 DNS 已被接管。

Lite 模式下，系统代理可以和 TUN 同时保持启用。这不是重复接管错误：系统代理继续服务遵循 OS 代理设置的应用，TUN 负责系统级流量路径。

## 5. 切换配置

TUN 运行期间切换配置时，`0.0.16-rc.8` 会根据新旧配置的所有权交接运行状态：显式 `runtime.tun` 优先于客户端缺省值；新配置不再需要旧 TUN 时会按新的期望状态协调。交接失败时客户端会尽量恢复切换前状态并记录错误。

因此切换后应同时观察：

- 当前配置名称；
- 系统代理状态；
- TUN 是否运行及其配置来源；
- 节点/URLTest 当前选中项是否已经更新到新配置。

不要只根据按钮是否亮起判断切换成功。

## 6. 关闭服务

点击“关闭服务”会撤销由 ZNet Sink 管理的系统代理设置。为了保留连接监控和快速恢复能力，普通断开不会以停止内核进程作为前提。

TUN 与系统代理是两个不同入口。若 TUN 仍在运行，应单独关闭 TUN；关闭本地管理的 TUN 后，设置中的启动参数才会重新允许修改。

## 7. 选择节点与模式

连接服务运行后，可以在概览或节点页切换策略组选中项，并在全局、规则和直连模式之间切换。策略组的实际成员和可用操作以当前配置及客户端显示状态为准。
