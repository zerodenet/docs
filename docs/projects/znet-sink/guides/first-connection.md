# 完成第一次连接

跟着这一页完成安装、导入来源和开启代理，最后用浏览器验证。你需要一条自己的订阅链接，或服务提供方给出的 Zero JSON 配置；安装 ZNet Sink 本身不会提供代理节点。

## 1. 下载并安装客户端

打开[客户端下载页](/download)，核对系统和芯片架构，选择对应安装包。日常使用优先选择正式版；只有明确需要试用新功能时再选预发布版本。

| 你的电脑 | 选择与安装方式 |
| --- | --- |
| Windows x86_64 | 下载 `.exe` 或 `.msi`，双击并按安装向导完成 |
| Apple 芯片 Mac | 下载 `aarch64.dmg`，打开后把 ZNet Sink 拖入“应用程序” |
| Intel Mac | 下载 `x64.dmg`，打开后把 ZNet Sink 拖入“应用程序” |
| Ubuntu / Debian x86_64 | 下载 `.deb`，用软件安装器打开；或在下载目录运行 `sudo apt install ./文件名.deb` |
| Fedora / RHEL 系 x86_64 | 下载 `.rpm`，用软件安装器打开；或在下载目录运行 `sudo dnf install ./文件名.rpm` |
| 其他 Linux x86_64 | 下载 `.AppImage`，在下载目录运行 `chmod +x ./文件名.AppImage`，再运行 `./文件名.AppImage` |

命令里的“文件名”要替换成下载文件的实际名称。`.sig` 和 `latest.json` 是校验或更新资料，不是安装程序。当前提供的是桌面包，不要下载其他平台的文件尝试安装到手机。

打开 ZNet Sink，首次引导选择**专业模式**。它允许只开启系统代理，先不启用需要额外系统权限的 TUN；简约模式的电源按钮会同时开启这两项。以后可以在标题栏或设置中切换模式。

如果 macOS 提示应用损坏或无法验证开发者，先确认来自官方发布页，再按[安装问题说明](./installation#macos-提示应用-已损坏)处理。

## 2. 安装 Zero 内核

客户端负责操作界面，Zero 内核负责实际转发，两者都需要准备。

1. 打开“设置 → 版本管理”，进入“内核版本管理”。
2. 选择稳定版渠道中适用于当前电脑的版本，点击安装并等待完成。
3. 返回设置，确认显示有效的内核路径和版本。

如果已经有 Zero，可直接选择 `zero.exe`（Windows）或 `zero`（macOS/Linux）可执行文件。仅下载压缩包、看到版本列表或完成欢迎引导，都不代表内核已安装。

## 3. 添加并选中代理来源 {#_1-准备代理配置}

**有订阅链接时：**

1. 打开“订阅”，点击“新增”。
2. 填写名称和订阅 URL，格式保留“自动检测”，关联配置选择自动创建。
3. 保存后点击该订阅的同步按钮，等待成功提示。
4. 回到“概览”，在“当前配置”中选择这份订阅生成的配置。

同步返回网页、登录页或授权错误时，检查链接是否失效。Zero 远程订阅需要 Base64 编码的 Zero JSON；其他格式应由服务提供方提供受支持的订阅。不要公开完整链接，其中可能含访问凭据。

**有本地 Zero JSON 文件时：**打开“配置 → 新建配置”，选择文件或粘贴 JSON，保存时选择“设为当前”。也可以保存后回到概览选择它。不要把其他内核的 JSON 配置当成 Zero 配置直接导入。

完成后，概览应显示刚添加的配置名称。保存订阅、同步内容和选中当前配置是三个不同步骤。

## 4. 启动内核并选择节点 {#_7-选择节点与模式}

1. 在概览的“内核状态”卡片点击“启动内核”，等待内核就绪。此时先不要开启 TUN。
2. 如果配置提供策略组，到“节点”页选择要使用的组，再选择其中一个可手动切换的节点。
3. 可对节点测速，等待结果；自动选择的 URLTest 组由内核决定成员，无需强行手选。
4. 回到概览，通常先保留“规则”模式，按配置决定哪些目标走代理。

“全局”使用全局代理出口，“直连”直接访问目标；可选项由配置和内核决定。如果配置没有策略组，就使用它已指定的出站。测速显示响应延迟，不是下载带宽。

## 5. 开启系统代理 {#_3-开启服务}

在概览的“内核状态”卡片点击“开启系统代理”，等待状态显示已开启。客户端会确认本地代理入口可用，再设置操作系统代理。

这个步骤只开启系统代理，暂不需要修改 DNS、Fake-IP 或 TUN 参数。它适用于遵循系统代理设置的浏览器和应用。

Linux 的自动集成使用 GNOME `gsettings`。在其他桌面环境，或应用不遵循系统代理时，可在该应用的 HTTP 或 SOCKS5 代理设置中填写概览显示的实际本地主机和端口。缺省通常为 `127.0.0.1:7890`，应以界面实际值为准。

## 6. 用浏览器验证 {#_2-检查概览状态}

打开浏览器，访问你实际需要的网站。**系统代理显示已开启，而且目标网站可以正常访问，就完成了第一次连接。** 测速数字、流量曲线或公网 IP 查询不能单独代替这个验证。

无法访问时，先按下面顺序检查：

1. 概览中的当前配置与所选节点是否正确；确认没有误选直连模式。
2. 内核和系统代理是否已就绪。点击“检查网络”，查看“需关注”或自测结果。
3. 提示端口占用时，关闭占用该端口的其他程序，或到“设置 → 网络”修改本地代理端口。
4. 配置或内核报错时，打开日志，先处理最早的一条错误；不要同时改多项设置。
5. 只有探测地址或公网 IP 查询失败时，仍要测试实际目标网站；检测服务本身也可能不可达。

仍不能连接，再按[故障排查](./troubleshooting)中对应现象处理。

## 7. 停止代理 {#_6-关闭服务}

在专业模式概览点击“关闭系统代理”，等待关闭状态。如果你另外开启过 TUN，也要单独关闭。

Zero 进程可以继续运行以保留监控和管理能力。进程仍在不表示系统流量仍被接管；需要完全退出时，使用客户端退出操作，并留意是否有清理失败提示。

## 之后需要接管更多应用时 {#_4-按需启用-tun}

浏览器已经可用，其他应用仍不遵循代理设置时，再按 [TUN 指南](./tun)开启流量接管。它会创建虚拟网卡并调整路由，需要系统权限。

简约模式中央电源按钮同时开启或关闭系统代理和 TUN。如果只需要系统代理，可以一直使用专业模式的独立开关，不必更改模式。

## 换一份来源时 {#_5-切换配置}

专业模式在概览“当前配置”中选择；简约模式使用“配置来源”。切换后检查名称、节点和网站访问。提示运行中的 TUN 参数不一致时，先关闭 TUN，再切换并重新开启。

日常的订阅同步和自动更新设置见[订阅管理](./subscriptions)，不需要重新走一遍安装流程。
