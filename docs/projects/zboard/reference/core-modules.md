# 核心模块与交付边界

ZBoard 围绕用户、订阅、节点和服务四个模块组织基础能力。以下说明适用于开发分支的设计与管理入口，尚未随新版本发布。

| 模块 | 管理内容 | 对其他模块提供的能力 |
| --- | --- | --- |
| 用户系统 | 用户、内容与公告、工单、用量观测 | 账户身份、用户状态和支持记录 |
| 订阅系统 | 商品、销售规格、订单、订阅实例、客户端模板 | 经订单履约确认的有效期、配额和访问权益 |
| 节点系统 | 服务器、节点协议、前置入口、权限组、流量对账 | 可用线路、认证凭据、配置交付和用量上报 |
| 服务系统 | 系统配置、插件、任务队列、维护、运行日志和审计 | 窄接口、异步执行、配置和可追溯的操作结果 |

工作台汇总这些模块的状态。已有外部供应商、DNS 和证书管理保留为兼容接入能力；后续插件替代应先完成依赖与数据迁移，并验证原有服务仍可用。

## 从商品到客户端线路

服务器保存资产和运行环境。节点协议保存代理协议参数；前置入口引用一个父协议并提供另一个公开地址。权限组分别选择可交付的直连协议和前置入口，商品引用权限组，销售规格定义价格、周期与购买用途。订单履约后产生或调整订阅实例，系统按该实例的权限与状态生成凭据和客户端配置。

仅授予前置入口时，系统为父协议生成认证凭据，并向客户端下发入口地址。父协议直连地址需要单独授权才会下发。多个入口和直连服务可共用父协议凭据；认证及流量计费归父协议，排行中的父协议统计也可能包含多个入口的流量。

外部转发入口用于登记已由外部软件或网络提供的转发地址。面板托管转发则关联承载服务器，由面板配置 Zero 转发。删除外部入口会撤销对应的面板交付权限，外部转发软件的停止与清理由其管理员负责。最后一个访问授权撤销后，父协议认证权限也应撤销。

## 销售操作与订阅状态

新购、续费、套餐切换、流量加购和重置流量均由实际可售 SKU 决定。用户购买重置规格并完成订单结算后，恢复目标订阅的本周期套餐配额，到期时间及自动重置日期保持原值。插件通过声明的宿主能力参与流程，普通扩展钩子不会直接绕过订单结算授予购买权益。

套餐切换按原订阅剩余时间与流量价值计算抵扣，最终报价、支付和履约必须一致。管理员手动调整配额或消耗使用独立的管理入口及审计记录。

流量暂时耗尽和订阅生命周期结束分别判断。可恢复的周期订阅在额度耗尽后仍可管理；具备实际续费能力的订阅结束后停止服务，保留七天续费恢复窗口。不可续费、无重置的固定配额订阅到期或耗尽后清理实例，订单摘要保留结束状态。历史记录不会继续提供代理访问权限。

## 菜单、扩展与验证

内置页面和插件页面统一注册为数据库菜单节点。后端决定页面入口和可用状态；默认模块调整只更新仍保持旧默认展示值的节点，管理员修改的名称、位置或隐藏状态保留。稳定节点 ID 也保留插件的挂载关系。

节点协议和权限组列表使用后端筛选与分页。直连与前置入口的编号范围分别处理，批量选择以有数量上限的服务端 ID 快照为准。SQLite 是默认回归和性能基准，MySQL 验证迁移、事务及锁兼容性。存储查询、本地接口、节点配置发布与实际客户端连接分别验证；测试通过不代表生产部署已经完成。
