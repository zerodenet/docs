# 服务器、线路与订阅 {#核心模块与交付边界}

遇到界面名称不清楚时，可以用这张表区分。第一次配置直接跟随[完整教程](../guides/)，不需要先读完参考页。

| 名称 | 你管理的是什么 |
| --- | --- |
| 服务器 | 一台可通过 SSH 管理、运行 Zero 的主机 |
| 节点协议 | 在服务器上运行的代理协议、监听端口和对外地址 |
| 前置入口 | 转到已有父协议的另一个连接地址，可以由面板托管，也可以由外部软件维护 |
| 权限组（节点组） | 允许某类订阅使用的直接协议与前置入口 |
| 商品与销售规格（SKU） | 一份套餐及其额度、周期和可用操作 |
| 订阅 | 某个用户实际获得的访问范围、期限和额度 |
| 订阅模板 | 客户端配置格式、策略组、规则和本地入口 |

## 配置怎样到达客户端 {#从商品到客户端线路}

套餐选择权限组，订单确认后创建订阅。面板根据这份订阅生成认证凭据和客户端配置。用户只会看到已授权且可交付的线路，不会自动获得服务器上的所有协议。

仅分配前置入口时，系统会为父协议生成所需凭据，但不会额外下发父协议直连地址。需要两种连接方式时分别授权，详见[前置入口](../guides/network-fronting#权限与订阅)。

## 订单与订阅有什么不同 {#销售操作与订阅状态}

订单记录一次开通或调整，订阅是实际可用的服务。保存零金额订单也需要管理员确认才会开通；有了历史订单，不代表服务仍在有效期内或还有流量。

续费、切换、加购和重置以实际可用规格及结算摘要为准；操作方法见[分配与管理订阅](../guides/plans-and-orders)。

## 保存后还要检查什么 {#菜单、扩展与验证}

保存成功只表示面板接受了设置。影响节点的变更还需要发布，用户随后更新客户端配置并验证真实连接。按[发布与恢复](./node-config-delivery)检查失败任务，不能只凭“在线”或“已启用”判断线路已可用。
