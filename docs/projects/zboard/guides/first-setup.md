# 首次初始化

面板启动且 `/readyz` 正常后，在浏览器打开 `https://你的面板域名/setup`。这一页创建站点和第一个管理员；服务器与协议在安装完成后配置。

## 初始化流程

1. **环境检查**：确认后端和数据库连接正常。失败时先修复服务，再继续。
2. **站点设置**：填站点名称和 HTTPS 公开地址。只做自用或由你分配账户时，关闭公开注册即可。
3. **系统策略**：确认时区和历史保留天数；不确定时可先保留默认值。
4. **首个管理员**：设置邮箱和强密码，完成安装，再通过 `/login` 登录。

管理员也是用户，可以使用个人中心。不要把管理员权限授予仅需要使用订阅的人。

## 系统时区

用 `Asia/Shanghai`、`UTC`、`America/Los_Angeles` 等 IANA 时区名称。向导优先预填浏览器时区，无法识别时使用 `UTC`；不要填写 `UTC+8`。

时区影响页面显示、“今天”和每日用量统计的日期边界，不会重写历史时间。选实际需要的时区即可，安装后仍可修改。

## 历史保留策略

| 设置 | 默认值 | 清理范围 |
| --- | --- | --- |
| 审计日志 | 180 天 | 超期审计记录 |
| 运行历史 | 90 天 | 已结束的节点、发布、证书和供应商操作 |
| 运营任务 | 90 天 | 已完成任务及任务项 |

取值为 `0–3650`，`0` 表示永久保留。这组设置不清理流量计量、订单、订阅与支付等业务历史。根据排障需要和磁盘空间选择，保留期限不是备份。

## 安装事务

点击完成后，站点设置、系统策略和管理员一起保存。失败时留在安装页，按错误修正后重试；不要另外手工插入管理员记录。安装成功后不能再次通过 `/setup` 创建管理员。

## 安全建议

- 使用 HTTPS，并核对公开地址；节点也需要能访问该地址完成上报。
- 保存好部署密钥和备份，尤其凭据加密密钥；不要在重启时重新生成。
- 自用先关闭公开注册，需要分享时创建普通账户即可。
- 公开注册、邮件验证或第三方登录按需配置，不是安装必做项。

## 完成第一条线路

安装向导结束后，按下面顺序做完一次完整交付：

1. [添加服务器](./node-management)，保存并验证 SSH，安装 Zero；确认本机服务和控制接口健康。
2. [创建协议](./protocol-services)，填写可供客户端连接的对外地址与端口，放行防火墙并检查发布记录。
3. 在“权限组”创建例如“自用线路”的组，勾选刚才的协议。
4. 在“商品与套餐”创建套餐并关联该组，设置额度、有效期和适用客户端模板；发布商品，添加可用于“新开订阅”的规格。
5. 在“订单管理 → 分配订单”选择自己的账户、套餐及规格，应付金额设为 `0`，填写自用原因并保存。**然后仍需执行“确认收款”才能开通**，零金额不需要实际付款。详细界面步骤见[订阅分配](./plans-and-orders#self-use)。
6. 等待凭据生成和相关节点再次发布成功，切到个人中心“订阅配置”，选择刚开通的订阅，复制对应客户端格式的链接。
7. [导入客户端](./subscriptions-and-traffic#客户端导入)，更新配置、选择线路并实际连接；随后在“流量明细”核对该订阅的用量。

成功时你应看到：有效订阅、正确线路、成功的节点发布、真实客户端连接和对应流量。只看到管理员首页或“订单创建成功”还未完成第一条线路。

## 下一步

自己先用通，再按[日常使用与分享](./daily-operations)为其他人创建普通账户与独立订阅。第三方登录、转发、邮件与支付等在需要时再配置。
