# 首次初始化

完成部署后，需要初始化管理员、站点基础配置和全局运营策略，再开始接入节点环境。

## 初始化流程

1. 创建管理员账户；
2. 配置站点名称、公开访问地址和注册策略；
3. 选择系统时区；
4. 设置审计日志、运行历史和任务历史的保留天数；
5. 进入后台配置节点连接凭证；
6. 验证数据库、缓存和运行环境；
7. 开始添加节点资源。

管理员、站点配置和首次系统策略会作为一次安装事务写入。时区或保留策略校验失败时，应修正表单后重新提交，不需要清理半创建的安装记录。

## 系统时区

使用标准 IANA 时区，例如：

```text
Asia/Shanghai
America/Los_Angeles
UTC
```

系统时区决定后台统一的时间展示、Dashboard 的“今天”边界以及按日/小时聚合语义。不要填写 `UTC+8` 这类固定偏移字符串。

它是全站运营时间语义，不会把数据库中的历史时间点改写成新的时刻。后续修改时区后，界面和新的日历聚合会立即使用新设置。

## 历史保留策略

首次安装可以设置：

- 审计日志保留天数，默认 `180`；
- 运行历史保留天数，默认 `90`；
- 任务历史保留天数，默认 `90`。

允许范围为 `0–3650` 天，`0` 表示永久保留。具体清理范围和升级后的默认行为见[运营概览与系统设置](./operations)。

## 安全建议

- 管理员密码使用高强度随机密码；
- SSH 凭证使用最小权限，并完成主机身份验证后再执行节点系统操作；
- 不在日志中记录明文凭证；
- 定期轮换外部服务密钥；
- 根据实际审计要求选择历史保留周期，不要只为了减少数据库体积而过度缩短。
