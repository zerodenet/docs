# 获取订阅与查看用量 {#订阅交付与流量展示}

已经拿到账户和有效订阅的用户，从本页开始即可。管理员还未分配访问时，先完成[开通订阅](./plans-and-orders#self-use)。

## 客户端导入

1. 登录个人中心，打开“订阅配置”。
2. 选择要使用的**具体订阅**，核对有效期和剩余流量。同一账户的不同订阅分别管理。
3. 选择匹配客户端的格式，复制该订阅的链接。
4. 在客户端的“添加订阅/从 URL 导入”中粘贴链接，更新配置并选择线路。使用 ZNet Sink 时选 Zero 格式；Clash/Mihomo 和 sing-box 分别选对应格式。
5. 启用客户端代理或需要的 TUN，实际访问一个目标，再到个人中心“流量明细”核对用量。

不要把浏览器打开链接的结果当成客户端导入测试。面板会识别请求客户端，普通浏览器或 `curl` 可能只得到跳转页面。

## 订阅生成链路

服务器协议决定线路与凭据，权限组决定可使用范围，订阅模板决定输出格式、策略组、规则和本地入口。用户拿到的是这份订阅的最终配置。

管理员调整这些设置后，先检查节点发布和管理端预览，再让客户端更新订阅。禁用协议会从后续订阅输出与节点配置中移除该服务。

## 单订阅访问边界

每个链接只属于一份订阅，不会合并同一账户的其他订阅。节点筛选只能缩小范围，不能增加权限；无匹配项可能返回空配置。

在目标订阅的访问管理中可以轮换或撤销链接。轮换后更新自己所有设备上的链接，旧链接不能继续下载。**这不等于轮换已下载的协议凭据或立刻断开已有连接**；停止分享须同时处理账户/订阅/线路权限及节点发布，见[日常使用](./daily-operations#调整或停止分享)。

链接等同于访问秘密。不要贴进公开聊天、截图或工单；Base64 只是编码，不是加密。

## 客户端识别与输出格式

| 选择的格式 | 导入结果 |
| --- | --- |
| Zero / ZNet Sink | Base64 编码的完整 Zero 配置 |
| Clash / Mihomo | 完整 Clash/Mihomo 配置 |
| sing-box | 完整 sing-box 配置 |
| Shadowrocket / v2rayN | Base64 编码的节点分享链接 |
| Quantumult X | `server_remote` 兼容节点资源 |

节点订阅只包含其渲染器支持的协议，不携带 ZBoard 的完整路由、策略组或本地入站。不能把节点订阅当作完整配置导入。

受支持的客户端会携带相应 User-Agent；ZNet Sink 使用 `ZNet-Sink/<版本>`。浏览器、空 User-Agent、普通 `curl` 或不匹配的标识会进入订阅伪装跳转。管理员自己改过的模板不会在每次升级时被默认模板覆盖。

## 无效订阅链接

已撤销、无效或非客户端请求会返回不可缓存的 HTTP 302，跳转到站点设置的订阅伪装地址（未设置时使用公开站点地址）。不要把跳转页保存成订阅配置。

更新失败时先核对客户端、所选订阅状态和链接是否已更换，随后检查响应状态与最终地址。不能仅凭跳转判断令牌一定存在或不存在。

## 本地 Mixed 端口

完整配置模板默认 Mixed 端口为 `7890`，范围为 `1–65535`，绑定本机 loopback。它供本机应用使用，不是远端服务器端口。

端口占用时在订阅模板修改，再更新客户端；也可按需要只用 TUN，但完整配置的 Mixed 与 TUN 不能都关闭。Shadowrocket、Quantumult X、v2rayN 等节点订阅由客户端自己管理本地入口。

## 托管规则与 ZRS

管理员在“订阅系统 → 规则集”添加来源，再在模板中使用。面板校验后为 Zero 编译 ZRS，Clash/sing-box 使用各自的格式。同步失败保留上次有效内容。

数据库只保存部分规则信息，源文件和产物另存于托管规则目录；[备份](./storage-and-backups)必须同时保存两者。

## 策略组输出

在完整配置模板中调整线路分组、测速、`DIRECT` 和 `REJECT`。后两者可按需启停，不作为测速候选。节点名称与展示顺序由协议服务统一控制。

默认测速 URL 为 `http://www.gstatic.com/generate_204`。自定义地址需要目标客户端/内核支持；不要因为测速成功就忽略实际代理访问测试。

## 规则集与客户端兼容性

导入的是独立规则集，不是任意客户端完整配置片段。未知条件和空内容会失败。

进程名/进程路径条件可供支持的平台上的 Clash/sing-box 使用，当前 Zero 规则路径不执行这类条件，相关来源不能作为 Zero ZRS 使用。详见[规则兼容性](../reference/managed-rule-compatibility)。DNS、TUN 和控制接口也应按目标客户端配置，不能直接混用专属字段。

## 流量计费与分钟级使用明细

用量来自 Zero 实际上报、成功归属到这份订阅的流量事实，再应用配置的倍率。它可能与客户端本地统计不同，尤其线路或套餐有倍率时。

用量明细会按分钟及用户、订阅、节点、协议和倍率聚合。合并后的一行不等于一次连接；原始记录仍保留用于核对。管理员需要检查原始明细时再使用接口的 `view=raw`，常规使用不必了解内部表结构。

## 趋势与活跃连接

先选时间范围，再看总量与趋势。日期边界按站点配置的系统时区计算，字节单位变化只影响展示。

“未采集”表示没有相应观测，不等于零。`active_flows=0` 只表示没有活跃连接，不表示节点或 Connector 离线。

## 流量与到期邮件提醒

管理员可以按需开启[订阅告警](./announcements-and-email#subscription-alerts)，提醒流量不足、耗尽或即将/已经到期；默认不发送。是否可用仍以个人中心的订阅状态、额度和有效期为准，不要等邮件才检查。

## 排查订阅与流量

| 现象 | 先检查 |
| --- | --- |
| 导入后是网页或空白 | 客户端格式、User-Agent、302 跳转、订阅是否有效 |
| 配置里没有线路 | 权限组、筛选、额度、协议启用状态和最近发布结果 |
| 有线路却连不上 | 对外地址/端口、防火墙、协议及证书、真实节点状态 |
| 连接正常但用量未变化 | 所选订阅、流量倍率、节点上报及事件处理积压 |
| 更新后本地代理无法启动 | Mixed 端口冲突、客户端版本和配置格式 |

更多步骤见[故障排查](./troubleshooting)。排错时隐藏完整链接和协议认证秘密。

## 在页面中查用量与对账

用户进入“流量明细”；管理员进入“节点系统 → 流量与对账”。选择日期和具体订阅，分别看统计摘要、趋势与分页记录。翻页只改变明细页，当前页合计不是整个区间用量。

协议详情中的“重置统计”需要填写原因，只开始新的展示统计周期；不会删除原始流量记录、恢复订阅额度或改变计费。对账时不要把协议的“本期累计流量”当成订阅已用流量。

加载失败不等于没有流量。发现不一致时保留原始记录调查，不通过改统计数字掩盖差异。续费与额度调整见[订阅与订单](./plans-and-orders)。
