# 分配订阅与管理订单 {#套餐、订单与用户交付}

订阅决定某个用户能用哪些线路、用多久、用多少流量。当前 ZBoard 用“商品（套餐）→ 销售规格（SKU）→ 订单确认”创建或调整订阅；这套记录同样可以用于自用和免费分享。

先完成[节点接入](./node-management)与[协议配置](./protocol-services)。在线支付插件、公开注册和对外销售都不是下面操作的前提。

## 开通自己的第一份订阅 {#self-use}

1. **选账户。** 管理员也能使用个人中心，可以直接给自己的账户开通；想分开日常使用和管理时，在“用户系统 → 用户管理”创建普通用户，状态设为启用，不授予管理员权限。
2. **选线路。** 在“节点系统 → 权限组”创建一个组，例如“自用线路”，选中刚才的直接协议，保存。旧页面中的“节点组”指同一类资源。
3. **建套餐。** 在“订阅系统 → 商品与套餐”创建一个套餐，关联该权限组，设置流量额度与需要的客户端模板；发布商品，并添加允许“新开订阅”的可用销售规格，明确有效期和流量规则。
4. **分配。** 在“订单管理 → 分配订单”选择自己、套餐及规格，权益操作选“新开订阅”。自用或免费分享可把这笔订单的应付金额设为 `0`，原因填写“自用分配”或实际分享用途。
5. **确认开通。** 保存后仍是待付款订单。核对用户、金额和权益，再使用界面上的“确认收款”完成确认。零金额分配不需要实际付款；有金额的订单须核实实际到账后才能确认。
6. **取配置。** 等待订阅生成和相关节点重新发布成功，进入个人中心“订阅配置”，选择这份订阅，按[客户端导入步骤](./subscriptions-and-traffic#客户端导入)连接。

管理员分配不是直接改数据库额度，也不会因保存表单自动开通。找不到可选套餐或规格时，先检查商品已发布、规格可售且支持所选操作。

## 管理员准备商品

自用可以只保留一个套餐和一个规格。需要不同线路、有效期或额度时，再新增对应方案。

- 权限组控制可交付的线路，不直接把整台服务器的所有协议授予用户。
- 规格控制价格、周期、购买用途和权益；“一次性付费”不自动等于永久有效。
- 对外提供购买入口时，从访客“套餐价格”和账户“购买套餐”检查实际可见内容与结算摘要。
- 当前商品和规格删除采用归档，保留历史订单快照；不要把删除商品当成撤销已开通订阅。

## 用户购买与领取配置

需要用户自行选择时：打开“购买套餐” → 选择商品与规格 → 核对结算摘要 → 创建订单 → 按站点提供的方式处理订单。订单完成并生成订阅后，再到“订阅配置”导入客户端。

已有待处理订单先检查原订单，避免重复下单。创建订单、完成结算、生成权益和客户端可连接是四个不同结果。

## 管理员分配与确认订单

分配记录保留管理员、原价、应付金额和原因。重复提交同一次操作不会重复创建订单；已确认订单的重复确认不会重复发放权益。

在线支付渠道是可选插件能力，核心负责订单结算和权益规则。当前宿主已有受控集成接口，但安装面板本身不等于已安装支付插件或配置收款渠道，见[插件说明](../plugins/)。

## 续费、切换与加购

先选择**具体订阅**，再操作；同一个账户可以有多份订阅。页面只提供已有可售规格支持的操作。

| 操作 | 需要核对什么 |
| --- | --- |
| 续费 / 补充额度 | 新周期、额度及是否延长期限，以规格和结算摘要为准 |
| 切换套餐 | 目标权益与抵扣；当前周期流量耗尽不一定禁止切换。切换不等于重置已用流量或追加一个周期 |
| 流量加购 | 目标订阅和加购额度；不要误选其他订阅 |
| 重置流量 | 需要对应重置规格及订单确认；恢复本周期基础额度，不延长到期时间或移动下次自动重置日 |

自动周期重置、购买流量重置和管理员手动调整是不同操作。管理员调整应填写原因，保留原始流量事实与审计记录。

流量暂时耗尽不等于订阅已结束。可续费的周期服务结束后先停止访问，并保留七天续费恢复窗口；不可续费的一次性服务可能在到期或额度耗尽后清理实例，历史订单保留结束状态。已清理的目标不能靠迟来的付款恢复，处理前先检查当前订阅状态。

## 管理订单问题

在订单详情核对用户、状态、规格与关联订阅。确认后仍无线路时，继续检查权限组、订阅状态和节点发布记录，而不是反复确认收款。

分享账户的具体方法和停止分享见[日常使用与分享](./daily-operations)。订阅链接泄露时见[访问链接管理](./subscriptions-and-traffic#单订阅访问边界)。
