# 节点与协议服务管理

节点是运行 Zero 的服务器；协议服务是服务器对外开放的一条线路；权限组（旧称节点组）决定哪些线路可以分配给用户。先接入一台服务器，再配置协议，不需要先接入云厂商账号。

## 资源关系

服务器 → Zero → 协议服务 → 权限组 → 用户订阅 → 客户端配置。

一台服务器可运行多个协议。DNS、证书和供应商账号是按需关联的独立资源。

## 新节点接入

1. 准备一台有公网可达地址的 Linux x86_64/systemd 服务器，以及面板能使用的 SSH 账号、密钥或密码。
2. 打开“节点系统 → 服务器管理”，新建服务器，填地址、SSH 端口和认证信息。
3. 保存后验证 SSH 与提权权限。确认是你要管理的主机，再进入“内核与运维”。
4. 选择可安装的 Zero 版本，提交安装，查看任务直到完成。安装操作被接受后会在后台继续，关闭页面不等于取消。
5. 检查 Zero 进程与控制接口健康，再检查节点到面板公开地址的连接和 Connector 上报。
6. 继续[创建协议](./protocol-services)。BBR、云厂商、DNS 和证书可等需要时再配置。

SSH 端口、面板 HTTPS 地址和协议服务端口用途不同，应分别检查网络及防火墙。SSH 验证成功并不保证用户协议端口可达。

## 区分三种运行状态

| 状态 | 正常意味着什么 |
| --- | --- |
| Zero / Kernel | 二进制已安装，systemd 服务及控制接口健康 |
| Connector | 节点事件最近成功送到面板 |
| 业务流量 | 用户实际连接与字节已被观测 |

新节点没有用户时，流量为零是正常状态。内核健康但上报暂时缺失时，按 Connector 警告排查面板地址和事件投递，不要仅因此反复重装内核。

## Zero 版本选择与发布

面板版本与 Zero 版本独立。选择面板列出的明确发行版本，区分正式版与预发布版；以节点实际安装版本、能力提示和发布结果为准。版本号本身不能证明所有协议和托管用户能力均已验证。

部署配置默认 `ZBOARD_ZERO_KERNEL_CONTRACT=legacy`。`native-local` 和 `native-local-mieru` 需要管理员准备匹配的可信本地制品和版本，不能只修改开关来增加协议支持。页面显示某协议不可用时，先按提示核对构建和兼容性，保留已有记录供检查。

升级前保留可恢复的版本与配置；批量升级选择固定目标版本，先用一台节点验证真实连接再扩大范围。

## 协议服务

到“节点协议”配置协议、监听端口、对外地址和需要的 TLS/REALITY/传输参数。订阅名称可使用容易辨认的地点或用途，不必包含内部编号。具体步骤见[协议服务配置](./protocol-services)。

## 新节点的 bootstrap inbound

尚未配置实际协议的新节点可能包含仅监听 `127.0.0.1`、端口为 `0` 的管理用入站。它不出现在用户订阅中，也不是对外可用线路。某些协议没有有效用户凭据时也不会启动业务监听；开通订阅后检查再次发布的结果。

## 发布流程

保存协议只是记录期望配置。完整过程包括编译、目标节点校验、激活与本机健康检查；随后还要单独检查 Connector 上报和真实客户端连接。

失败时从“运行日志”或该协议的发布记录读取**第一条错误**。修复后重试，避免只反复点击发布而忽略端口冲突、证书路径或内核能力错误。

## 自动发布与重试

开通订阅、到期、额度耗尽、修改协议或权限组都会触发相关节点配置更新。后台队列持久保存待办，并在失败或重启后重试；节点离线时可能继续使用旧配置。

任务接受、任务完成、节点实际生效分别核对。重复执行可能发生，队列为空也不能证明 Connector 在线。详见[配置发布与恢复](../reference/node-config-delivery)。

## BBR 与主机操作

BBR 是可选优化，不是安装成功条件。在“内核与运维”查看真实主机状态，再决定是否调整；目标内核和系统必须支持，执行后检查实际状态与任务结果。

## 删除节点与远端清理

删除面板记录不会通过 SSH 停止远端 Zero，也不会替你删除云服务器。因此先完成正在进行的安装/发布，按[节点清理](./node-cleanup)停机，再删除面板记录。

面板可提供独立清理脚本；已部署该脚本的主机也可使用 `/usr/local/sbin/zboard-zero-cleanup`。`stop` 停止并禁用服务但保留文件；`uninstall` 才清理托管文件，使用前检查范围。面板删除后仍可能保留历史订单、订阅、流量与审计记录。

## 权限组与订阅配置 {#节点组与运营配置}

在“权限组”选择可交付的直接协议或前置入口，再由套餐关联该组。它引用具体服务，不直接授予整台服务器。按[分配订阅](./plans-and-orders#self-use)给自己或其他用户开通访问。

## 日常检查

- 实际 Zero 版本符合预期，Kernel 和 Connector 分别正常。
- 最近配置发布成功，客户端能连接到预期线路。
- 订阅状态、额度和权限组正确，完成流量能归属到对应用户。
- 使用域名或证书时检查解析、有效期和绑定。

遇到问题先看[故障排查](./troubleshooting)，无需先研究底层控制接口。
