# 运营概览与系统设置

Zboard `v0.0.1-dev.26` 将后台首页、系统时间语义和运行历史保留策略统一到一套面向运营的管理模型。本页说明 Dashboard 应如何阅读，以及哪些系统设置会影响全站展示和历史数据维护。

## Dashboard 的时间范围

后台 Dashboard 支持：

- 今天；
- 最近 7 天；
- 最近 30 天。

“今天”和按日聚合的边界使用 Zboard 配置的**系统时区**，而不是管理员浏览器自己的时区。修改系统时区后，新的全局展示和日历聚合语义立即按新时区生效。

系统仍保存精确的时间点；时区设置主要决定运营界面的日期边界、时间格式和按日/小时聚合方式，不应被理解为修改历史记录本身的发生时间。

## 业务与服务健康

Dashboard 不再只是资源数量汇总，而是把当前需要判断的运营状态分成几类：

### 业务

包括当前时间范围内的：

- 实收收入与上一周期对比；
- 已支付订单、新购订单和续费订单；
- 新增订阅；
- 当前有效订阅；
- 临近到期订阅。

存在多币种订单时，不应把不同币种直接相加成一个看似精确的单币种金额；界面会区分混合币种状态。

### 服务

包括：

- 当前时间范围内的业务流量；
- 已启用节点和在线节点；
- 在 principal flow 数据覆盖可用时展示活跃连接/订阅观测。

某项观测数据没有覆盖时，界面应表达“暂无覆盖”，而不是把未知值当成 0。

### 需要关注

关注项表示**当前仍未解决的业务状态**，例如：

- 离线节点；
- 未解决的协议发布问题；
- 待处理工单。

历史上已经失败但后来恢复的任务，不应长期留在“需要关注”里制造噪声。

### 基础设施

用于快速查看：

- 节点总量与启用量；
- Connector 在线覆盖；
- 已验证 SSH 的节点；
- 已具备流量上报条件的节点；
- 协议端点与启用端点；
- 已发布套餐；
- 当前未解决的部署问题。

Dashboard 是运营入口，不替代节点详情、任务记录和审计日志。需要定位具体异常时，应继续进入相应资源页面查看事实链路。

## 系统时区

系统时区使用 IANA 名称，例如：

```text
Asia/Shanghai
America/Los_Angeles
UTC
```

`UTC+8` 这类固定偏移字符串不是有效的系统时区值。使用 IANA 名称可以正确处理夏令时和历史时区规则。

建议选择运营团队用于订单、流量和日常报表的统一业务时区。它是**全局展示与日历语义**，不要根据单个用户、商户或浏览器动态切换查询边界。

## 历史保留策略

系统设置可以分别配置：

| 配置 | 默认值 | 作用 |
|------|--------|------|
| 审计日志保留天数 | `180` | 清理超过期限的审计日志 |
| 运行历史保留天数 | `90` | 清理已结束的节点操作、协议发布、证书和供应商操作 |
| 任务历史保留天数 | `90` | 清理已经结束的任务历史 |

允许范围为 `0–3650` 天；`0` 表示永久保留。

保留策略只清理已经满足过期条件的历史记录，不应删除仍在执行的任务或把当前未解决状态从业务资源中抹掉。Zboard 后台会周期性执行清理，不需要管理员手工逐表删除。

调整保留时间前先确认组织的审计、故障复盘和合规需求。缩短周期后，已经超过新阈值的历史记录可能在后续清理周期中被删除。

## 首次安装时的系统策略

新安装可以在初始化阶段同时设置：

- 系统时区；
- 审计日志保留天数；
- 运行历史保留天数；
- 任务历史保留天数。

这些字段与管理员账户、站点名称等初始化数据在同一安装事务中写入；校验失败时不应留下“管理员已创建但系统策略未完成”的半安装状态。

旧部署升级后，如果没有主动设置，会使用服务端默认值。之后可以从系统设置继续调整。

## 关于页面

后台“关于”页面提供当前运行实例的项目和版本信息，包括：

- Zboard 版本；
- 发布通道；
- 进程启动时间与运行时长；
- 安装时间；
- 开源许可证；
- 源码、文档、Release、Issue 和社区入口。

排查升级或反馈问题时，优先从这里确认当前实例真实版本，而不是只根据镜像标签、浏览器缓存或部署目录名称判断。

## 与节点运营的关系

Dashboard 和系统设置负责全局视角；节点本身的运行诊断、SSH 资源采样、BBR 系统操作和 Zero 发布状态仍在节点工作流中处理。详见[节点与协议服务管理](./node-management)。

流量趋势和订阅用户维度的统计语义见[订阅交付与流量展示](./subscriptions-and-traffic)。
