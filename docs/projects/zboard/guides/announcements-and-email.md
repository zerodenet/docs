# 公告、注册验证与邮件

站点公告用于网页内通知；SMTP 用于验证码、邮件任务和按需启用的订阅提醒。两者分别配置，可以按场景配合使用。

## 发布站点公告

1. 进入“用户系统 → 站点公告”，点击“新建公告”。
2. 填写标题和 Markdown 正文，从用户视角预览检查内容与链接。
3. 选择级别和受众：所有人、仅访客、登录用户或仅管理员。
4. 先保存草稿；准备发布时选择“已发布”，设置开始和结束时间。留空分别表示立即生效、长期有效。
5. 需要首页提醒时勾选弹窗，选择是否允许直接关闭，再点击“保存公告”。
6. 使用对应受众的页面检查实际展示；尚未到开始时间的公告不会提前显示。

正文支持标题、粗体、列表、引用、代码和安全的 HTTP(S) 链接。时间输入以当前浏览器本地时间填写，保存时转换为绝对时间。

首页提醒最多加载最新 5 条当前有效公告。登录用户可在“公告中心”查看历史与已读状态；关闭或点击“我知道了”会确认阅读。关闭“允许直接关闭”后仍可通过“我知道了”收起。

到期公告退出提醒区，但保留在公告中心。**归档会立即从用户视图和未读统计中移除**；要保留用户可查的历史，设置结束时间即可。草稿或已归档公告可永久删除，已发布公告应先归档。

## 开放注册与邮箱验证

1. 打开“服务系统 → 邮件与运营模板”，配置 SMTP 主机、端口、发件人、TLS 和凭证，保存后确认通道状态。
2. 进入“服务系统 → 注册与验证”，设置“允许访客注册”。关闭它不会删除已有账号或影响已有用户登录。
3. 需要验证邮箱时启用“注册时验证邮箱”；SMTP 未就绪时先修复邮件配置。
4. 在访客注册页确认验证码发送、收取和注册结果。

邮箱验证码为六位、10 分钟有效，并受重发冷却、尝试次数和网络频率限制。当前图形验证码入口尚未接入，不能当作已经启用的防护功能。

## 欢迎通知与运营邮件

“注册与验证”中的“注册成功通知”管理唯一的注册触发模板。启用后，注册成功会创建可重试的欢迎邮件任务；停用欢迎模板不影响注册前的验证码。

运营邮件模板在“邮件与运营模板”管理。发送后到“服务系统 → 运营任务”检查任务和收件人的具体结果，再检查实际收件箱。验证码是注册前同步发送，欢迎通知是注册后排队执行，排查时应先区分哪一条链路失败。

SMTP 保存成功只说明配置已接受；任务排队成功也不保证最终送达。失败时核对主机、端口、TLS、凭证、发件地址及任务错误，避免反复创建相同通知。

## 订阅流量与到期提醒 {#subscription-alerts}

告警由管理员统一配置，四个开关默认都关闭。需要提醒自己或使用者时：

1. 进入“服务系统 → 邮件与运营模板”，保存 SMTP 配置。填写“测试邮件收件地址”，点击“发送测试邮件”，到收件箱确认；“测试连接”只检查通道，不发送邮件。
2. 打开并保存“邮件任务开关”，允许发送运营邮件。只启用 SMTP 不会打开这个总开关。
3. 找到“订阅告警”，按需要启用“余量不足提醒”“流量耗尽提醒”“即将到期提醒”和“已到期提醒”。逐项点击对应的“保存”，不要只修改输入框。
4. 设置阈值和同一用户的提醒间隔，保存后在“运营任务”检查实际任务、收件人结果与收件箱。

| 设置 | 默认值 | 可选范围 |
| --- | --- | --- |
| 流量不足阈值 | 剩余 20% | 1–90% |
| 即将到期窗口 | 3 天 | 1–30 天 |
| 同一用户的最短提醒间隔 | 24 小时 | 6–168 小时 |

提醒间隔由同一用户的不同订阅和告警类型共享，不是每份订阅各有一个额度。收到一封提醒后，其他符合条件的提醒可能延后；不要把阈值当作即时发送保证。

系统只向符合条件的有效账户邮箱发送，并在实际投递前重新检查订阅状态、告警开关和发送资格。续费或补充额度后，已经不适用的待发提醒会被跳过。告警会持久去重，避免重复扫描或重启反复创建同类通知；但服务端发送成功仍不能替代用户收件验证。

没有收到时，依次检查 SMTP 实际投递、邮件任务总开关、对应告警开关、已保存的阈值、用户邮箱与账户状态、共享间隔和任务结果。订阅告警用于通知，不代替订阅状态、流量扣账或节点访问控制。
