# 日常使用与分享 {#后台导航与日常运营}

已连通自己的第一条线路后，再按需要添加用户、扩展线路和调整用量。本页按 [v0.0.2 RC 文档基线](../#选择版本)的默认菜单说明；升级会保留管理员已修改的菜单名称、位置和隐藏状态。

| 默认入口 | 常用页面 | 用来做什么 |
| --- | --- | --- |
| 概览 | 运营工作台 | 看整体状态、用量和待处理事项 |
| 用户系统 | 用户管理（页面标题“用户与权限”）、公告、工单、Fair Use 观测 | 管理使用者、通知及问题反馈 |
| 订阅系统 | 商品与套餐、订单、订阅管理、订阅模板与规则集 | 分配访问范围、周期和客户端配置 |
| 节点系统 | 服务器管理、节点协议、权限组、流量与对账 | 管理自己的服务器、线路与实际发布 |
| 服务系统 | 系统设置、插件、任务、日志、维护、关于 | 增加可选能力、排错与备份升级 |

已有供应商、DNS 和证书入口仍可使用；接入自己的服务器不要求先配置这些集成。

## 分享前检查 {#开始营业前}

1. 在自己的客户端上实际连接成功，并确认流量能够归属到自己的订阅。
2. 在“用户与权限”给对方创建普通用户，或按需要配置[公开注册](./announcements-and-email)。创建用户不要求开放注册。
3. 按[分配订阅](./plans-and-orders#self-use)为这个用户单独开通访问，选择允许分享的权限组、有效期和额度；免费分享可分配零金额订单并确认。
4. 让对方用自己的账户进入“订阅配置”，复制对应客户端的链接。不要把管理员账户或自己正在用的同一份订阅当成多人账户分享。
5. 在订阅列表核对对方的独立用量。需要通知维护时间时，再使用公告或工单。

只做自用时可以保持公开注册关闭，不必为了完成首次连接先填写收款渠道或公开销售页面。

### 调整或停止分享

调整线路时编辑对应权限组；它会影响引用该组的订阅，保存前检查影响范围。变更后等待凭据协调与相关节点发布完成，再让客户端更新订阅。

停止某个账户继续使用时，在用户管理中变更其状态，并核对相关节点更新结果。移除线路、停用协议或结束订阅也需要发布到节点；离线节点可能保留旧运行配置。紧急停机按[节点清理](./node-cleanup)处理。

轮换或撤销订阅链接只控制后续配置下载，不能当成已下载协议凭据的即时撤销。不要把链接轮换当作停止分享的唯一措施。

## 处理用户连接问题

先定位用户及**具体订阅**，核对状态、有效期、流量、权限组和协议发布结果。需要复现时记录客户端版本、时间及报错，不要把完整订阅链接放进公开工单。

按[订阅与流量](./subscriptions-and-traffic)检查配置下载，按[故障排查](./troubleshooting)检查真实连接。任务被接受、队列执行完成和客户端连接成功分别核对。

## 使用 Fair Use 观测

在“Fair Use 观测”搜索具体订阅，选择时间范围，检查覆盖情况后再解释趋势。当前入口用于只读观测和实验分析，不会自动通知、限速或处罚用户。未采集不等于零连接，风险评分也不直接等于违规。

## 升级与恢复

在“关于 ZBoard”核对**完整版本号和渠道**。面板与节点 Zero 分别升级，不能只看其中一个版本。先保存数据库、部署配置与密钥、规则、插件及事件队列，再按[升级步骤](./maintenance#upgrade)操作。

恢复后除了检查首页和 `/readyz`，还要检查订阅下载、真实连接、任务和节点上报是否恢复。
